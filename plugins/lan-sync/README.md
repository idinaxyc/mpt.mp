# lan-sync — синхронизация плееров по локальной сети

Плагин для mpt.mp. Один файл `main.py`, только стандартная библиотека Python 3.8+, ~0 нагрузки
в простое (один–два лёгких запроса к ядру в секунду, пока играет музыка; когда пауза — реже).

## Что синхронизируется

| Что | Как |
|---|---|
| Воспроизведение: очередь, текущий трек, позиция, пауза/play | один «регистр», позиция досчитывается по времени, а не пересылается постоянно |
| Громкость | регистр |
| Тема (11 цветов + имя) | регистр; на другом устройстве меняется на лету |
| Плейлисты | **объединение** по имени (без учёта регистра): добавляются недостающие плейлисты и треки |
| Файлы треков | недостающие скачиваются с другого устройства в `<первая папка библиотеки>/mpt-sync/` (или `download_dir`) |

Не синхронизируются: настройки самих плагинов (в том числе токен), пути, горячие клавиши.
Удаление и переименование плейлистов **не** переносится (иначе нужны «надгробия», а потеря данных
хуже лишнего плейлиста).

Треки сопоставляются между устройствами по паре «имя файла (без регистра) + размер» — id у каждого
устройства свои. Два разных файла с одним именем и размером будут считаться одним.

## Быстрый старт

1. Скопируйте папку `lan-sync` в `~/mpt.mp/plugins/` на каждом устройстве.
2. Включите плагин (страница «ПЛАГИНЫ») и подтвердите права.
3. В настройках на всех устройствах задайте **одинаковый токен** (от 8 символов; лучше длинная
   случайная фраза). Без токена плагин ничего не делает.
4. Устройства найдут друг друга сами (UDP-широковещание на порту 47821). Если сеть режет
   broadcast (гостевой Wi-Fi, VPN, некоторые роутеры) — впишите адреса в поле «peers»:
   `192.168.1.5:47821, 192.168.1.7:47821`.
5. Откройте порт 47821 **TCP** (обмен) и **UDP** (поиск) для локальной сети в файрволе.

Строка статуса плагина: `устройств рядом: N · ведущее: <имя>`.
Кнопки: «Синхронизировать сейчас», «Показать устройства».

## Кто главный

Постоянного главного устройства нет — «главное» то, чьё изменение последнее.

* У каждого изменения есть метка **HLC** (гибридные логические часы):
  `max(время в мс, самая большая метка из виденных) + 1`.
* Побеждает изменение с большей меткой; при равенстве — с большим id устройства.
  Все устройства приходят к одному результату независимо от порядка доставки.
* Устройство, которое уже получило чужое изменение, ставит на своё следующее метку больше —
  поэтому оно «побеждает как текущий главный». Одновременные изменения (в пределах задержки сети)
  решаются по времени, затем по id: проигравшее откатывается к выигравшему.
* Расхождение часов не ломает схему: после первого обмена метка «догоняет» самую большую.
  Но изменения с устройства, у которого часы убежали вперёд, будут выигрывать до первого
  ответного изменения.

Отличие от исходной идеи «если ни одно не было главным — не применять»: так устройства могли бы
навсегда остаться в разных состояниях, поэтому конфликт всегда решается детерминированно.

Игнорируется эхо: изменения, которые плагин сам внёс в плеер по чужому указанию, не
отправляются обратно. Трек, которого нет на устройстве, скачивается (если разрешено), а пока
играет следующий из очереди; после скачивания очередь применяется снова.

Известные ограничения: очередь длиннее 3000 треков не синхронизируется; если пользователь
нажимает паузу в тот же момент (меньше секунды), когда применяется чужая перемотка, пауза может
быть перебита; при подключении устройства оно принимает текущую очередь и тему, если они новее.

## Безопасность

* Каждый запрос подписан HMAC-SHA256 от токена (метка времени, одноразовое число, метод, путь,
  хеш тела) и принимается один раз; ответы тоже подписаны. Токен по сети не передаётся
  и не пишется в журнал.
* Файлы передаются с подписью (HMAC) в конце потока — подмена по дороге будет замечена,
  но трафик **не шифруется**: любой в сети может его прочитать. Используйте только в доверенной сети.
* Запрос файла — по ключу «имя|размер»; пути от клиента не принимаются, имя файла очищается от
  разделителей и недопустимых символов. Одновременно отдаётся не более 2 файлов.
* Все значения из сети проверяются (цвета — строго `#rrggbb`, очередь ≤ 3000, громкость 0…1).
* Хотите отдавать, но не скачивать (или наоборот) — настройки `share_files` и `download_missing`.

## Проверка

```bash
python3 tests/test_sync.py          # два фейковых ядра и два процесса плагина на localhost
python3 ../../tools/mpt_plugin_host.py .   # проверка манифеста и протокола
```

Тест проверяет: громкость, очередь/позицию/паузу, смену «главного», одновременные изменения,
тему, объединение плейлистов, передачу файла с проверкой содержимого, отказ чужому токену.
